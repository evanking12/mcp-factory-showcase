# Hard-Family Failure Signal Map

## Purpose

This is the canonical routing table for hard-family and full-suite failures.

Raw logs are not branch decisions. A hard-family observation must first become a
canonical signal key, then route to an owner, baseline row, confidence level,
and next action.

The target shape is:

```text
observed hard/full-suite failure
-> canonical signal key
-> breakpoint family or measurement row
-> owner
-> current tier or baseline state
-> confidence
-> next recommended campaign
```

Measurement-fabric row ownership lives in
[`HARD-FAMILY-MEASUREMENT-FABRIC.md`](HARD-FAMILY-MEASUREMENT-FABRIC.md). This
map is the routing table; the measurement-fabric doc is the row inventory and
tier ladder for runner/API/discovery/bridge/Ghidra/artifact authority.
Compiled-suite green claim ceilings live in
[`COMPILED-SUITE-GREEN-CONTRACT.md`](COMPILED-SUITE-GREEN-CONTRACT.md), which
prevents compatibility or measurement green from being treated as product-green.

## Maintenance Rule

Update this file at the end of every campaign that:

- runs hard-family, full-suite, Required, Medium01, or comparable end-to-end
  evidence;
- changes failure terminalization, analyzer authority, lane comparability,
  dependency blocking, or finalization closeout;
- creates, removes, renames, or reclassifies a failure signal; or
- classifies an observed failure as `new_breakpoint_family`.

A campaign closeout is not operator-reviewable if it produces or reinterprets a
hard/full-suite failure signal and leaves this map stale.

New or sharpened Hard02 signals must also record their family routing before
the next campaign proceeds. If the signal cannot yet be mapped, the closeout and
next-branch packet must say `family_unknown` with the reason and the next
classification step. Do not treat an unmapped Hard02 signal as ordinary local
pipeline noise.

## Signal States

| State | Meaning |
| --- | --- |
| `active_blocker` | Current next blocker for hard-family progress. |
| `known_signal` | Canonical key exists and routes to an owner, but it is not the active blocker. |
| `covered_guard` | The signal is guarded by a passing measurement, survivability, or lane-comparability contract. |
| `failed_baseline_row` | The signal maps to a failed tier row and should remain visible until fixed. |
| `new_breakpoint_family` | No current row owns the signal; add or recommend adding one before treating it as ordinary noise. |

## New Signal Intake

When a hard-family or full-suite run produces a signal not listed above:

1. Normalize the raw observation into a proposed key.
2. Try to route it to an existing row in `HARD-FAMILY-MEASUREMENT-FABRIC.md`,
   `STAGE-PROVING-MAP.md`, a per-stage inventory, or
   `ENTERPRISE-SURVIVABILITY-SUITE.md`.
3. If no row fits, classify it as `new_breakpoint_family`.
4. Add or recommend a provisional signal key, provisional family row, likely
   owner or `owner_unknown`, low claim ceiling, and next classification proof
   before choosing a fix campaign.
5. Do not claim the signal is understood until it has an owner, evidence paths,
   and tier position.
